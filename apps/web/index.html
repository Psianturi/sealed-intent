Your AI agent can ask for money. It can't take it.

Sealed Intent sits between an AI agent and its wallet on NEAR. Every payment the agent wants to make is checked first: is the deal real, who gets the money, was the agent tricked, is it within budget. Only then does the money move, and every decision leaves a sealed receipt.

The problem, in one picture

An AI agent with a wallet is like a new employee handed the company card. It works fast and never sleeps, but it can be fooled, it can mistype an address, and it can take a bad price without noticing. Unlike a person, it does all of this in seconds, and on a blockchain nothing can be undone.

✉

It gets tricked

A message that looks like it comes from the boss says "send everything to this account now." Agents have paid attackers this way. Grok and Bankr, May 2026, about $150K reported.

⇄

It takes a bad deal

A swap route that returns a fraction of the real value can still pass a slippage check, because the check trusts the same bad quote. Aave / CoW, March 2026: $50M became about $36K.

⌘

Its request path gets hijacked

Well-formed withdrawal requests get signed because they look right, not because they are right. Binance, October 2026, about $6.3B.

These happened to exchanges, protocols and people, not to Sealed Intent users. We do not claim it would have saved them. The Arena replays their patterns against an agent on NEAR and shows what holds and what does not.

How it works

The agent never holds the key. It sends a request; Sealed Intent runs five checks and answers with a traffic light.

1 · Is the deal real?

The quote from NEAR Intents must be genuinely signed, name exactly the token, amount and receiver the agent declared, and return value close to the reference price. A look-alike token or a route that loses 26% is refused.

2 · Who gets the money?

Known partner, brand-new account, an account that does not exist, a contract whose code changed, or an address on a shared blocklist. New or unknown receivers go to a human first.

3 · Is this even a payment?

Only swaps, transfers and approved contract calls are allowed. Adding a key, deploying code or signing a message that moves funds is refused and freezes the wallet until the owner looks.

4 · Was the agent tricked?

The instruction text is screened for "ignore your rules" patterns, and a second opinion comes from an AI running in a sealed hardware enclave that is verified before it sees anything. The AI can only make a decision stricter, never looser.

5 · Is it within budget?

Per-payment and daily limits, counted per agent by the server, so an agent cannot rename itself for a fresh budget. If the outcome of a payment is unclear, it counts as spent.

Then: a traffic light

ALLOW the money moves through custody. WARN a human decides first; the agent cannot approve itself. BLOCK nothing leaves the wallet.

Sealed receipts: proof without exposure

Every decision produces a receipt that anyone can check, but that reveals nothing private. The verdict and the reasons are visible. The amount, the receiver and the instruction are replaced by sealed commitments.

  • Edit one character and the receipt becomes invalid.
  • An auditor needs one fact? The owner opens that one field, and the receipt proves it matches.
  • Live receipts also carry the enclave's signature over the exact question it was asked, verified against Intel and NVIDIA hardware evidence.

Where it fits

Any agent

Agents talk to Sealed Intent through a standard tool interface (MCP) or a plain web API. They get a verdict and generic reasons, never the secret policy or its thresholds.

NEAR custody and Intents

Approved payments are signed inside a custody enclave (OutLayer), and swaps settle through NEAR Intents. The agent never touches a key.

The owner stays in charge

Only the owner's token can approve a WARN, freeze or unfreeze the wallet. A freeze survives restarts.

What is real today, and what is not

  • Real: the rules shown here are the same code that runs live; quotes from NEAR Intents and their signatures; hardware attestation of the AI enclave verified on our own machine; key behaviour confirmed on a local NEAR node.
  • Simulated in the Arena: the chain is an in-memory ledger with real NEAR token rules; quotes, the enclave opinion and custody are stand-ins; the agent is scripted and follows every message, so the Arena tests what happens after an agent is fooled, not whether it can be.
  • Not done yet: a real custody execution and a mainnet swap; binding the network connection to the enclave; isolating the Sealed Intent host from the agent.
  • Out of reach by design: a stolen key, a bug inside a token contract, or a compromised Sealed Intent host. The Arena shows these as escapes on purpose.
