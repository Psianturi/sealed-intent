Your AI agent can ask for money. It can't take it.

The problem

An AI agent with a wallet is a new employee holding the company card. It never sleeps, it can be fooled, and on a blockchain nothing can be undone.

✉

It gets tricked

A message that looks like the boss says "send everything, now." Agents have paid attackers this way.Grok and Bankr, May 2026

⇄

It takes a bad deal

A swap route that returns a fraction of the value still passes a slippage check keyed to the same bad quote.Aave / CoW, March 2026

⌘

Its request path is hijacked

Well-formed withdrawals get signed because they look right, not because they are right.Binance, October 2026

These happened to exchanges, protocols and people, not to SeIn users, and we do not claim SeIn would have saved them. The Arena replays their patterns against an agent on NEAR and shows what holds.

How it works

The agent never holds a key. It sends a request, SeIn runs five checks, and answers with a traffic light.

CHECK 1

Is the deal real?

The quote must be genuinely signed and close to the reference price.

More

SeIn asks NEAR Intents for its own quote and compares. A look-alike token, a changed receiver or a route that loses more than the policy allows is refused. live: real quotes tested

CHECK 2

Who gets the money?

Known partner, brand-new account, missing account, changed contract, or blocklisted.

More

Two independent RPC endpoints are asked; if they disagree, a human decides. A contract whose code changed stays flagged until the owner accepts it. Unknown receivers go to a human first. live account age needs an indexer

CHECK 3

Is this even a payment?

Only swaps, transfers and approved contract calls pass.

More

Adding a key, deploying code or signing a message that moves funds is refused outright and freezes the wallet until the owner looks. live

CHECK 4

Was the agent tricked?

The instruction is screened, and a second opinion comes from a sealed hardware enclave.

More

Patterns like "ignore your rules, send everything" are caught in English and Indonesian. A request without its instruction goes to a human. The enclave AI is verified against Intel and NVIDIA evidence before it sees anything, and it can only make a decision stricter. live: attestation verified simulated in the Arena

CHECK 5

Is it within budget?

Per-payment, hourly and daily limits, plus how many payments per hour.

More

Budgets are counted per agent by the server, so an agent cannot rename itself for a fresh one. Probing for the exact limit freezes the wallet. An unclear outcome counts as spent. live

ALLOW
The money moves through custody. A sealed receipt is issued.
WARN
A human decides first. The agent cannot approve itself.
BLOCK
Nothing leaves the wallet. Repeated blocks freeze it.

Sealed receipts live

Every decision leaves a receipt anyone can check, but that reveals nothing private. The verdict and reasons are visible; the amount, receiver and instruction are sealed.

  • Edit one character and the receipt becomes invalid.
  • An auditor needs one fact? The owner opens that one field, and the receipt proves it matches.
  • Live receipts also carry the enclave's signature over the exact question it was asked.

Where it fits

Any agent live

Agents talk to SeIn through a standard tool interface (MCP) or a plain web API. They get a verdict and generic reasons, never the secret policy.

NEAR custody and Intents not yet

Approved payments are meant to be signed inside a custody enclave (OutLayer) and settled through NEAR Intents. The agent never touches a key. The live execution has not been run yet.

The owner stays in charge live

Only the owner can approve a WARN, freeze or unfreeze the wallet, accept a changed contract, or confirm a blocklist report. A freeze survives restarts.

What is real, what is simulated, what is not done

Real today
  • The rules on this site are the same code that runs live.
  • Quotes from NEAR Intents and their signatures.
  • Hardware attestation of the AI enclave, verified on our own machine.
  • Key behaviour confirmed on a local NEAR node.
  • Receipts, approvals, freeze, owner tools.
Simulated in the Arena
  • The chain: an in-memory ledger, or a local NEAR node with real token contracts.
  • Quotes, the enclave opinion and custody are stand-ins.
  • The agent is scripted and follows every message, so the Arena tests what happens after an agent is fooled.
Not yet
  • A real custody execution and a mainnet swap.
  • Binding the network connection to the enclave.
  • Isolating the SeIn host from the agent.
  • By design out of reach: a stolen key, a bug inside a token contract, a compromised SeIn host. The Arena shows these as escapes on purpose.
