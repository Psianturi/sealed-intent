Your AI agent can ask for money. It can't take it.

SeIn (Sealed Intent) is a safety checkpoint between an AI agent and its wallet on NEAR. Every payment is checked before it moves: safe ones go through, unusual ones wait for the owner, scams are stopped. The rules stay secret, so an attacker cannot aim just under a limit it cannot see.

The problem

An AI agent with a wallet is a new employee holding the company card. It never sleeps, it can be fooled, and on a blockchain nothing can be undone.

✉

It gets tricked

A message that looks like the boss says "send everything, now." Agents have paid attackers this way.

Grok and Bankr, May 2026

⇄

It takes a bad deal

A route that returns a fraction of the value still passes a slippage check keyed to the same bad quote.

Aave / CoW, March 2026

⌘

Its request path is hijacked

Well-formed withdrawals get signed because they look right, not because they are right.

Binance, October 2026

These happened to exchanges, protocols and people, not to SeIn users, and we do not claim SeIn would have saved them. The Arena replays their patterns against an agent on NEAR and shows what holds.

How it works

The agent never holds a key. It sends a request, SeIn runs five checks, and answers with a traffic light.

  1. AI agentAsks. Holds no key.
  2. SeInFive checks, then a sealed receipt.
  3. Custody enclaveSigns only what SeIn allowed.
  4. NEARThe money moves.
1

Deal real?

The quote must be genuinely signed and close to the reference price.

More

SeIn asks NEAR Intents for its own quote and compares. A look-alike token, a changed receiver or a route that loses too much value is refused.

2

Who gets it?

Known partner, new account, missing account, changed contract, or blocklisted.

More

Two RPC endpoints are asked, and if they disagree a human decides. A contract whose code changed stays flagged until the owner accepts it.

3

A payment?

Only swaps, transfers and approved contract calls pass.

More

Adding a key, deploying code or signing a message that moves funds is refused and freezes the wallet until the owner looks.

4

Tricked?

The instruction is screened, then judged by an AI inside a verified enclave.

More

Known trick patterns are caught. A request without its instruction goes to a human. The enclave AI can make a decision stricter, never looser.

5

In budget?

Limits per payment, per hour and per day, plus how often it may pay.

More

The server counts per agent, so renaming itself gets an agent nothing. Probing for the limit freezes the wallet. An unclear outcome counts as spent.

✓ ALLOW

The money moves through custody.

! WARN

A human decides first. The agent cannot approve itself.

✕ BLOCK

Nothing leaves the wallet. Repeated blocks freeze it.

Private by default

A checker that reads your payments must not become the leak. Four layers keep the rules and the money private.

A secret policy Live

Encrypted at rest. The agent only learns "limit exceeded", never which limit or how much.

A private AI opinion Live

The enclave is verified against Intel and NVIDIA evidence before it sees anything. The connection is tied to that evidence, and the answer is signed.

Sealed receipts Live

The verdict is public. Amount, receiver and instruction are sealed. The owner can open one field for an auditor.

A private route Not yet

Policy can force payroll onto Confidential Intents. It hides origin and route, not the destination. The check exists; a live quote needs a NEAR Intents login.

What is real, what is simulated, what is not done

Real today
  • The rules: the same code runs in the Arena and live.
  • Quotes from NEAR Intents and their signatures.
  • The enclave check, on NEAR AI Cloud, with Intel and NVIDIA evidence and the TLS binding. A real run is kept as evidence.
  • Receipts, approvals, freeze and encrypted storage.
  • Payments through OutLayer custody on NEAR testnet, each with a transaction anyone can look up.
  • A public registry on NEAR testnet: signing keys, agents and receipt batches.
  • A hosted SeIn on testnet, the one that answers on the Try it page.

Check each of these from your browser.

Simulated in the Arena
  • The chain is a ledger, or local NEAR nodes with real token contracts. Both recordings match.
  • Quotes, the enclave opinion and custody are stand-ins there.
  • The agent is scripted and follows every message, so the Arena tests what happens after an agent is fooled.
Not yet
  • A mainnet swap or token payment. One small NEAR payment was made on mainnet; its receipts are in the repository.
  • A live confidential route.
  • A hosted SeIn for your own agent. The hosted one behind Try it is a shared testnet demo.
  • Encrypting the prompt to the model itself. Today it is protected up to the verified gateway enclave.

Out of reach by design: a stolen custody or owner key, a bug inside a token, a compromised SeIn host. All the limits.
